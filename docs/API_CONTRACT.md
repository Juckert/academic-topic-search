# API поиска учебных тем

Статус — контракт HTTP-обёртки над SearchPipeline. Реализация — topic_search/api.py, запуск описан в [LOCAL_RUN](LOCAL_RUN.md).

[Машиночитаемое описание OpenAPI](openapi.json)

Базовый путь — /api/v1. Формат — JSON в UTF-8. Версия контракта передаётся в api_version со значением 1.0. История, черновики и подборки хранятся в браузере.

Маршруты задаются без завершающего слеша. Клиент отклоняет перенаправления. Результаты проверки передаются с Cache-Control: no-store.

## GET /filters

Возвращает сведения о доступном каталоге и настройках поискового профиля.

| Поле | Содержание |
|---|---|
| api_version | 1.0 |
| dataset_id, dataset_version | Идентификатор и версия корпуса |
| corpus_size | Число исходных записей |
| departments | Уникальные непустые названия подразделений |
| years | Уникальные годы, числа |
| score_type | bm25, cosine, rrf или reranker_logit |
| candidate_limit | Максимальный размер выдаваемого пула, от 1 до 50 |

Значение department из запроса совпадает со строкой из departments. year передаётся числом. Пустой выбор передаётся как null.

## POST /search

~~~json
{
  "title": "Оценка устойчивости банков",
  "annotation": null,
  "filters": {
    "department": null,
    "year": 2026
  }
}
~~~

Название обязательно, после удаления пробелов по краям должно содержать букву или цифру. Длина названия — до 500 символов, аннотации — до 3498 символов. Пустая аннотация нормализуется в null. Backend соединяет название и аннотацию через два перевода строки. Итоговый текст укладывается в ограничение SearchPipeline в 4000 символов. Фильтры объединяются по AND и применяются до отсечения кандидатов.

Профиль поиска выбирается сервером. Клиент передаёт только текст и два предусмотренных фильтра.

### Результат

~~~json
{
  "api_version": "1.0",
  "search_id": "search-example",
  "query": {
    "title": "Оценка устойчивости банков",
    "annotation": null,
    "filters": { "department": null, "year": 2026 }
  },
  "method": "bm25",
  "reranker_enabled": false,
  "score_type": "bm25",
  "dataset_id": "academic-topics",
  "dataset_version": "corpus-v1",
  "pipeline_version": "bm25-v1",
  "corpus_size": 500,
  "eligible_documents": 34,
  "candidate_limit": 50,
  "candidate_count": 1,
  "status": "results",
  "empty_reason": null,
  "hits": [{
    "id": "topic-example",
    "title": "Исследование финансовой устойчивости банков",
    "annotation": "Пример описания задачи исследования.",
    "annotation_origin": "generated",
    "metadata": {
      "year": 2026,
      "department": "Финансы",
      "program": null,
      "work_type": "ВКР",
      "source_url": null
    },
    "score": 12.5,
    "score_type": "bm25",
    "retrieval_score": 12.5,
    "retrieval_score_type": "bm25"
  }]
}
~~~

Числа и запись в примере иллюстрируют формат.

| Поле | Смысл |
|---|---|
| search_id | Уникальный идентификатор выполненного поиска |
| query | Нормализованные входные поля и фильтры |
| method | bm25, dense или hybrid |
| reranker_enabled | Применялся ли cross-encoder |
| dataset_id, dataset_version | Корпус, по которому выполнена проверка |
| pipeline_version | Версия конфигурации и моделей |
| corpus_size | Размер корпуса до фильтров |
| eligible_documents | Число записей после фильтров, до поиска |
| candidate_count | Число кандидатов в ограниченном поисковом пуле |
| candidate_limit | Максимальный размер этого пула |
| status | results или empty |
| empty_reason | null, filters_or_exclusions или no_candidates |
| hits | Все кандидаты пула в порядке убывания score |

candidate_count равен длине hits и не превышает candidate_limit. Размер пула ограничен 50. При одинаковых оценках используется порядок по идентификатору. Значения id уникальны внутри ответа.

Пул возвращается целиком. Ограничение на 5, 10 или 20 строк и фильтр минимальной оценки применяет frontend. Эти действия сохраняют результат выполненной проверки и не добавляют запись в историю. Счётчик интерфейса относится к возвращённым кандидатам.

### Шкалы

| score_type | Интерпретация |
|---|---|
| bm25 | Балл лексического поиска, неотрицательный |
| cosine | Косинусное сходство, от -1 до 1 с допуском 0.000001 |
| rrf | Балл объединения рангов, неотрицательный |
| reranker_logit | Исходный конечный балл cross-encoder |

score_type одинаков в корне ответа и у всех hits. Без reranker он определяется методом поиска. С reranker итоговая шкала — reranker_logit. retrieval_score и retrieval_score_type сохраняют оценку этапа извлечения кандидатов.

Интерфейс показывает исходное число с названием шкалы. Процент используется только в демонстрационном поиске по словам. Критерии отнесения к дублям согласуются после оценки на размеченных данных.

### Описание найденной работы

В каждой записи передаются название, аннотация и метаданные. annotation_origin принимает original, generated, unknown или missing. Значение original используется для описания из подтверждённого источника. Для автоматически составленного текста передаётся generated. Отсутствующие сведения имеют значение null. Для отсутствующей аннотации используются annotation: null и annotation_origin: missing.

source_url содержит абсолютную HTTP(S)-ссылку без учётных данных или null. Тексты отображаются как обычный текст. Описание и ссылка сохраняются в браузерном снимке, чтобы история и подборки оставались читаемыми после обновления корпуса.

### Пустая выдача

Успешная проверка без кандидатов возвращает HTTP 200, status: empty, hits: [] и candidate_count: 0.

- filters_or_exclusions — область поиска пуста.
- no_candidates — область содержит записи, поиск не вернул кандидатов.

## Ошибки

~~~json
{
  "api_version": "1.0",
  "error": {
    "code": "invalid_request",
    "message": "Проверьте длину аннотации.",
    "field": "annotation"
  }
}
~~~

| HTTP | code | Ситуация |
|---|---|---|
| 422 | invalid_request | Некорректный текст или фильтр |
| 503 | search_unavailable | Корпус или модель недоступны |
| 500 | internal_error | Внутренняя ошибка |

Сообщение предназначено для пользователя и не содержит traceback, локальные пути или содержимое окружения. Ошибка сервера не подменяется демонстрационным ответом. Клиент отменяет устаревший запрос при изменении текста и ограничивает ожидание 30 секундами.

## Подключение SearchPipeline

Backend создаёт SearchPipeline один раз при запуске процесса. Для первого профиля подходит configs/search.json. В профиле threshold должен быть null. Для получения полного пула используется top_k=candidate_limit. Обёртка переводит filters в имена метаданных pipeline, дополняет найденные записи аннотациями из корпуса и собирает ответ по схеме.

Путь к корпусу, модели и поисковый профиль задаются конфигурацией сервера. Для браузерного запроса допустим только предусмотренный JSON. Рекомендуемые ограничения HTTP-обёртки — до 32 КиБ на запрос и до 3 МиБ на ответ.

При локальной разработке Vite перенаправляет /api на 127.0.0.1:8000. Для размещения под разными origin backend разрешает конкретный адрес frontend. Параметры VITE_* доступны браузеру. Секреты и серверные пути хранятся в окружении backend.
